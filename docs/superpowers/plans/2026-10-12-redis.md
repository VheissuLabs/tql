# Redis and Valkey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redis and Valkey connections open a key browser: keys in folding `:` namespaces scanned in the background, a view per type, edits written atomically on `:w`, TTL and rename, a database switcher and a command pane.

**Architecture:** `Driver::Redis`. A `keystore` module holds a `KeyStore` trait and its Redis implementation over the `redis` crate (sync, rustls TLS, through the existing SSH tunnel). A new `tui/keys` screen implements `Tui` beside the table browser and reuses the chrome, the grid, the status and hotkey bars, the palette, help, settings, the line editor and the value viewer. `browse.rs` opens it for a Redis connection and handles its exits like the table browser's.

**Tech Stack:** Rust 2024, `redis` 1.7 (sync), ratatui. Live servers `redis:7` and `valkey/valkey:8` (`TQL_TEST_REDIS`, `TQL_TEST_VALKEY` as `host:port`).

**Spec:** `docs/superpowers/specs/2026-10-12-redis-design.md`

## Global Constraints

- No code comments; warnings and clippy deny; commit to `main`; full check exit 0 before each push; commit messages end with the Claude-Session line.
- Scan with `SCAN … COUNT 1000`, never `KEYS`; stop at 100,000 keys and say so.
- Every pending change goes in one `MULTI` … `EXEC` on `:w`.
- A read-only connection refuses edits, and its command pane runs only commands `COMMAND INFO` flags `readonly`.
- Blocking and streaming commands are refused in the command pane: `subscribe`, `psubscribe`, `ssubscribe`, `monitor`, `sync`, `psync`, `blpop`, `brpop`, `blmove`, `brpoplpush`, `bzpopmin`, `bzpopmax`, `bzmpop`, `blmpop`, `xread` / `xreadgroup` with `block`, `wait`, `waitaof`.
- Shell commands that need SQL (`query`, `describe`, `tables`, `export`, `dump`, `load`, `sync`) and MCP refuse a Redis connection with "a Redis connection is not a SQL database".

## Review Focus

1. **A huge keyspace:** the screen stays responsive while scanning and stops at 100,000. Pinned in Task 3.
2. **A list item that moved between reading and `:w`:** not removed; `:w` says so and keeps the change. Pinned in Task 4.
3. **A key that expires or is deleted by someone else while shown:** the value pane says it is gone, not an error dump. Pinned in Task 3.
4. **Binary values:** shown as hex with their length, never as mangled text, and not editable as text. Pinned in Task 3.
5. **A write command typed on a read-only connection:** refused before it is sent. Pinned in Task 5.

**Interfaces (produced):**

```rust
pub enum KeyKind { String, Hash, List, Set, Zset, Stream, Other(String) }
pub struct Scanned { pub cursor: u64, pub keys: Vec<String> }
pub enum Contents { Text(Vec<u8>), Rows { headers: Vec<String>, rows: Vec<Vec<String>>, more: bool }, Missing, Unsupported(String) }
pub enum Change {
    SetString { key: String, value: String },
    SetField { key: String, field: String, value: String },
    DeleteField { key: String, field: String },
    SetItem { key: String, index: i64, was: String, value: String },
    PushItem { key: String, value: String },
    RemoveItem { key: String, index: i64, was: String },
    ReplaceMember { key: String, was: String, value: String },
    AddMember { key: String, value: String },
    RemoveMember { key: String, value: String },
    SetScore { key: String, member: String, score: String },
    AddScored { key: String, member: String, score: String },
    RemoveScored { key: String, member: String },
    NewKey { key: String, kind: KeyKind, value: String },
    DeleteKey { key: String },
}
pub enum Reply { Nil, Text(String), Number(i64), List(Vec<Reply>), Map(Vec<(Reply, Reply)>), Error(String) }
pub trait KeyStore: Send {
    fn scan(&mut self, cursor: u64, pattern: &str, count: usize) -> anyhow::Result<Scanned>;
    fn size(&mut self) -> anyhow::Result<u64>;
    fn kinds(&mut self, keys: &[String]) -> anyhow::Result<Vec<KeyKind>>;
    fn ttl(&mut self, key: &str) -> anyhow::Result<Option<i64>>;
    fn read(&mut self, key: &str, kind: &KeyKind, offset: usize, limit: usize) -> anyhow::Result<Contents>;
    fn write(&mut self, changes: &[Change]) -> anyhow::Result<()>;
    fn expire(&mut self, key: &str, seconds: Option<i64>) -> anyhow::Result<()>;
    fn rename(&mut self, from: &str, to: &str) -> anyhow::Result<()>;
    fn databases(&mut self) -> anyhow::Result<Vec<(u32, u64)>>;
    fn select(&mut self, database: u32) -> anyhow::Result<()>;
    fn run(&mut self, line: &str) -> anyhow::Result<Reply>;
    fn reads_only(&mut self, command: &str) -> anyhow::Result<bool>;
    fn server(&mut self) -> String;
}
pub fn connect(connection: &Connection, encrypter: Option<&Encrypter>) -> anyhow::Result<Box<dyn KeyStore>>;
```
