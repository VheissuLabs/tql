v0.14.1

Fixes for the drivers 0.14.0 brought in: SQL Server, ClickHouse and Redis/Valkey.

Bug Fixes

- SQL Server: a read-only connection, and the MCP run-query tool, refuse a
  statement that carries use, commit, kill, dbcc or other T-SQL after a
  select. T-SQL needs no ; between statements, so these got past the check.
- SQL Server: queries slower than 30 seconds finish instead of failing and
  dropping the connection, and tql connects again when a connection drops.
- SQL Server: exports load back. Computed and rowversion columns are left
  out, identity values are kept, and very large floats are written with an
  exponent.
- SQL Server: column names complete in the SQL editor; hex typed into a
  varbinary column is written as bytes; contains, starts with and ends with
  match datetime and money values as the grid shows them; a filter copied to
  the editor keeps N'' on text; the editor keeps [a;b] names whole, splits on
  GO lines and keeps a procedure, function or trigger body together; and
  nvarchar, nchar, datetime2, time and datetimeoffset show their declared
  sizes.
- ClickHouse: tables page in a stable order, in the grid and in tql export,
  so rows are no longer skipped or repeated.
- ClickHouse: read-only users can connect, answers over 10 MB come through,
  and an error partway through a query shows ClickHouse's own message.
- ClickHouse: ssl_ca, client certificates and the TLS modes are honoured; a
  session is kept, so temporary tables and SET last between statements;
  written rows are reported; IPv6 hosts connect; and tql load replays into
  ClickHouse one statement at a time.
- Redis/Valkey: :w checks every key before writing and writes nothing if one
  is not the type the changes expect. If Redis may have taken only part of a
  write, tql drops the pending changes and shows what is there, rather than
  writing them twice.
- Redis/Valkey: N refuses a key that already exists instead of overwriting
  it.
- Redis/Valkey: a silent server times out instead of freezing tql, and a
  dropped connection reconnects.
- Redis/Valkey: ssl_ca, client certificates and the TLS modes are honoured,
  so self-signed and private-CA servers work.
- Redis/Valkey: binary key names stay apart; an ACL user sees the real types
  of the keys it may read; a rename with changes pending is refused; a very
  large string is shown in part; a read-only connection can run INFO, CONFIG
  GET and other read commands but not scripts; T says when the key does not
  exist; and stream entries keep repeated field names.

Changes

- ClickHouse arrays and maps show in ClickHouse's own syntax, ['a','b'] and
  {'x':1}, rather than as JSON.
