v0.11.0

Move whole databases around from the command line, and come over from
TablePlus.

New Features

- `tql dump`, `tql load` (or `import`) and `tql sync` copy a whole database,
  schema and data, from the command line.
- `tql dump <connection> [tables…]` writes a dump folder. MySQL goes through
  mydumper, Postgres through pg_dump, and SQLite is copied by tql itself.
  `--to` chooses the folder, `--database` another database on the same server,
  `--threads` sets how many tables run at once (4 by default), and
  `--data-only`, `--no-lock`, `--force` and `--dry-run` do what they say.
- `tql load <dump> <connection>` (alias `import`) loads a dump folder with
  myloader or pg_restore, or replays a `.sql` file from `tql export`.
  `--drop` replaces tables that already exist, and a replayed export runs in a
  single transaction: if a statement fails, nothing is loaded.
- `tql sync <from> <to> [tables…]` dumps one connection and loads into the
  other in one step, replacing the tables it brings over and leaving the rest
  alone. `--into` names the target database, and `--via` and `--keep` control
  the folder it passes through.
- Dump, load and sync show a live progress bar counting tables, with the table
  being worked on shown beneath it. `-v` prints everything the tools say
  instead, and `--dry-run` shows the exact command without running it.
- The database password never reaches the command line. It is handed to the
  tool in a private 0600 file that is removed when the command ends.
- A dump writes a `tql.json` manifest describing itself, so a load does not
  need to be told what it is. A dump folder must be new or empty, and tql
  checks there is free space before it starts.
- Dumping and loading stay within one kind of engine for now, so SQL Server is
  not supported by dump, load or sync.
- `tql tableplus` imports the connections TablePlus for Mac has saved, with
  their groups, environments as tags, SSH tunnels and TLS settings.
- Passwords come from the macOS Keychain, macOS asking before handing each one
  over; deny and that connection arrives without one. `--without-passwords`
  leaves them all in the Keychain.
- Connections tql already has are skipped, and drivers it does not speak are
  listed and left alone, so running `tql tableplus` twice is safe. `--dry-run`
  lists what would come over without touching anything, `--from` reads a
  TablePlus Data folder from elsewhere, and `--json` answers an agent.
- `tql open` and `tql connect` take SSH connection strings: a `+ssh` scheme
  with the SSH server first and the database behind it, such as
  `mysql+ssh://forge@203.0.113.7/forge:secret@127.0.0.1?name=app&env=production`.
  tql saves the tunnel with the connection and leaves the SSH key to your
  agent and `~/.ssh/config`.
- An `env` parameter in a connection string sets the tag: production, staging,
  dev or local.

Enhancements

- `tql open` and `tql connect` recognise more connection strings: postgres://,
  mssql:// and the `+ssh` forms above, beside mysql://, pgsql://, sqlsrv://
  and SQLite file paths.
- Naming an already-saved connection with `--name` renames it, and `--tag`
  sets its tag.
- If a dump or load tool is missing, tql says which tool it needs and how to
  install it.

Bug Fixes

- Connections reached through different SSH servers are no longer mistaken for
  one another: the SSH host is now part of the identity tql compares.
- A direct connection and an SSH-tunnelled one to the same host are kept apart
  as two connections.
