v0.15.0

Snowflake, over its SQL API with a programmatic access token.

New Features

- Snowflake connections: browse and query, every schema under folding
  headers, declared primary and foreign keys for links and paging, and every
  type shown as Snowflake writes it: dates, times, timestamps with their
  offsets, variants on one line and binary as hex. Tables, columns and keys
  come from SHOW commands, which do not wake the warehouse. Tables are read
  only in the grid, since Snowflake does not enforce primary keys; the SQL
  editor runs what the role allows (#8).
- The connection form asks a Snowflake connection for its Account, Database,
  Access token, Warehouse and Role. tql open and :open take
  snowflake://user:token@account/DATABASE?warehouse=WH&role=ROLE.

Bug Fixes

- Opening a connection string tql has already saved keeps the password it
  carries, and a Snowflake warehouse and role, rather than the ones saved
  before, so a changed password works the first time (#10).
- A connection with no port, libSQL or Snowflake, no longer shows a stray
  colon after its host in the connection list.
