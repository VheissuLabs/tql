v0.12.2

A round of fixes across the drivers, plus a little more room in the SQL editor.

Enhancements

- One column of space between the SQL editor's border and its text. The
  cursor, click targets and the completion list all move with it, so they still
  line up with the text.
- The driver is a type now rather than a string. A connection saved as mariadb
  is MySQL everywhere, including dump and load, a stored driver value tql no
  longer knows is skipped when the connection list is read instead of breaking
  it, and the default ports come from one place: MySQL and MariaDB 3306,
  Postgres 5432, SQL Server 1433.

Bug Fixes

- Read-only is enforced by the database, so a write cannot slip through. SQLite
  runs the statement with query_only, and MySQL and Postgres in a read-only
  transaction. SQL Server has no read-only transaction, so tql refuses a
  statement with a writing word such as update or into anywhere outside its
  strings and comments, which catches an OUTPUT clause or a write in a
  subquery, and runs the rest in a transaction it always rolls back. That
  covers the agent commands, the MCP query tool and the SQL editor on a
  read-only connection, and it catches a write hidden in a with that the old
  first-word check let through.
- Wide characters such as Chinese, Japanese and emoji are measured as two
  columns in the SQL editor, the row form, the filter value, the value viewer,
  the connection form and group rename, so they wrap, scroll, place the cursor
  and take clicks without eating a border or losing their end.
- An export pages through a table in the order of its whole primary key,
  composite keys too, and a failed key lookup stops the export rather than
  carrying on and paging in no order.
- An edit or delete that reaches no row now says so and stays pending instead
  of reporting it was written. MySQL counts matched rows, so an edit that
  changes nothing no longer looks like it missed, and sorting a query result
  only touches the statement's own order by and limit, never words inside
  strings, subqueries or comments.
- A MariaDB export loads back, Postgres shows the first result when several
  statements return rows, MySQL shows dates and times the same with or without
  a filter, and a whole real value stays a real when shown or exported.
- MySQL BIT columns show as numbers, and an edited or added bit is written back
  as a number.
- sync knows a database is itself however its host, port or MySQL flavour is
  written, so two connections that differ only in 127.0.0.1 versus localhost,
  or in a written-out port, are no longer taken for one another.
- The record inspector measures its related rows at full width, so it widens
  once when a relation opens instead of adding two columns on every redraw.
- The production safeguards for creating a database and sharing the screen read
  the tag whatever its case, as the dump guard does, and a huge status_seconds
  no longer panics.
- A mouse offset or a column drag can no longer push a position out of range,
  and a nonsense mouse_row_offset or mouse_column_offset in the config is held
  to ±1000.
- A corrupt stored password, an oversized MCP cursor, a nonsense last-update
  time or an extreme mouse offset no longer panics; ssh reads the host as the
  destination; a DSN takes a bracketed IPv6 host and decodes only real percent
  escapes; and the AI answer is found after braces in its reasoning.
- The SQL editor's text wrap returns early for a zero width instead of looping.
